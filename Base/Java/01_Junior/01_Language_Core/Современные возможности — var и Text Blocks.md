В современной Java (версии 10–22) акцент сместился на **читаемость кода** и **снижение когнитивной нагрузки**. Инструменты `var`, **Text Blocks** и **Unnamed Variables** позволяют убрать визуальный шум, оставляя на виду только суть алгоритма.
## `var`: Локальный вывод типов (Java 10+)

`var` — это не динамическая типизация (как в JS), а **синтаксический сахар** для статической типизации. Компилятор сам смотрит на правую часть выражения и подставляет нужный тип в байт-код.

### Где разрешен и запрещен `var`

|**Можно ✅**|**Нельзя ❌**|
|---|---|
|Локальные переменные внутри методов|Поля класса (instance/static variables)|
|Переменные цикла `for` и `for-each`|Параметры методов|
|Ресурс в `try-with-resources`|Возвращаемые типы методов|
|Параметры лямбда-выражений (Java 11+)|Инициализация `null` или без инициализации|

**Почему именно так:** в разрешённых случаях у компилятора всегда есть выражение-инициализатор прямо в точке объявления, из которого можно вывести конкретный тип (значение цикла, ресурс, инициализатор переменной). В запрещённых случаях такого выражения нет или тип обязан быть частью публичного контракта: поля, параметры и возвращаемый тип метода — это то, на что смотрит вызывающий код извне, и если бы их тип неявно выводился из внутренней реализации, любое изменение реализации могло бы незаметно изменить публичный контракт метода/класса. По той же причине инициализация обязательна и не может быть отложена: вывод типа происходит один раз, в момент объявления, и берётся строго из инициализирующего выражения — без него компилятору просто не от чего вывести тип.

### Особенности вывода типов

Если вы пишете `var list = new ArrayList<>();`, компилятор выведет тип `ArrayList<Object>`. Чтобы сохранить типизацию, нужно указывать тип справа: `var list = new ArrayList<String>();`.

> **Важно:** `var` — это не ключевое слово, а «зарезервированное имя типа». Это значит, что код `int var = 5;` технически скомпилируется (для обратной совместимости), но делать так — плохой тон.

## Text Blocks: Многострочные строки (Java 15+)

Текстовые блоки решают проблему «лесенки» из плюсов и символов `\n`, делая JSON, SQL и HTML внутри Java-кода читаемыми.

### Правила оформления

1. **Открывающие кавычки:** Должны заканчиваться переводом строки. Текст не может начинаться на той же строке, что и `"""`.
    
2. **Управление отступами (Incidental Whitespace):** Компилятор автоматически убирает «лишние» общие отступы слева, ориентируясь на самую левую позицию текста или закрывающих кавычек `"""`. На практике это значит, что положение закрывающих кавычек — не косметика: если сдвинуть `"""` левее самой левой строки текста, у всего блока появится дополнительный отступ (закрывающие кавычки становятся новой «нулевой» границей), а если сдвинуть их вровень с текстом — отступы слева пропадают полностью.

3. **Нормализация переносов строк:** независимо от того, как исходный `.java`-файл хранит переносы строк (`\r\n` на Windows или `\n` на Unix), компилятор при обработке текстового блока приводит все переносы к единому символу `\n` (LF). Это делает содержимое текстового блока переносимым: результат `.length()`/сравнения строк не зависит от того, в какой ОС и с какими настройками git был checkout'ed исходный код.

### Магия экранирования

- `\"` больше не нужно экранировать.
    
- `\` в конце строки — соединяет текущую строку со следующей (удаляет перенос).
    
- `\s` — гарантирует сохранение пробела (по умолчанию trailing spaces в конце строк текстового блока обрезаются).

## Unnamed Variables и Patterns (Java 22+)

Символ подчеркивания `_` официально стал «безымянной переменной». Это способ сказать компилятору и коллегам: «Мне нужно здесь что-то объявить по правилам синтаксиса, но я не собираюсь это использовать».

В отличие от обычной переменной с именем вроде `unused`, `_` не создаёт именованной привязки (binding) в области видимости — компилятор не резервирует под неё узнаваемое имя, а значит, `_` можно использовать несколько раз в одной и той же области видимости (например, несколько раз в одной цепочке `catch`-блоков или деструктуризации записи), не получая ошибку компиляции «переменная с таким именем уже объявлена». Плюс это явно и однозначно выражает намерение автора: код читающему сразу понятно, что значение сюда попадает не случайно забытым, а осознанно игнорируется — в отличие от `unused`, которое просто по конвенции подразумевает то же самое, но не гарантировано инструментами.

### Примеры использования

- **В блоках catch:** `catch (Exception _)` — если нам важен сам факт ошибки, а не её детали.
    
- **В циклах:** `for (var _ : list)` — если нужно просто выполнить действие N раз.
    
- **В деструктуризации Records:**

```java
if (obj instanceof Order(var id, _, var status)) { 
    // Нам важны только id и статус, остальное (_) игнорируем
}
```

## Резюме: Правила «хорошего тона»

1. **Принцип `var`:** Используйте его только тогда, когда тип **очевиден** из правой части (например, `var user = new User()`). Не используйте `var`, если справа стоит вызов метода с неясным возвращаемым типом (`var result = service.process()`).

2. **Unnamed `_`:** Используйте его всегда, когда переменная не используется. Это исключает предупреждения компилятора "Variable is never used" и делает код чище.
