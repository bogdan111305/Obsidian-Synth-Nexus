## Поля: Где живет состояние?

Класс определяет структуру, но данные живут в полях. Важно различать, где именно в памяти они располагаются:

- **Instance Fields (Поля экземпляра):** Уникальны для каждого объекта. Хранятся в **Heap**.
    
- **Static Fields (Статические поля):** Принадлежат классу, а не объекту. Хранятся в **Heap** — как часть объекта-зеркала `Class` (метаданные самого класса — байткод, constant pool, vtable — лежат в Metaspace, но не сами значения static-полей).
### Дефолтные значения

Если вы не инициализировали поле явно, Java сделает это за вас:

- Числа (`int`, `long`, `byte`, etc.) → `0` или `0.0`.
    
- `boolean` → `false`.
    
- `char` → `\u0000` (null-символ).
    
- Ссылки на объекты → `null`.

## Конструкторы и магия компилятора

Конструктор — это специальный блок кода для инициализации объекта.
### Правила игры:

1. **Дефолтный конструктор:** Компилятор генерирует `public ClassName() {}` только в том случае, если вы **не объявили ни одного** своего конструктора. Как только вы пишете хотя бы один конструктор (пусть даже с параметрами), компилятор перестаёт добавлять бесплатный no-arg вариант — если он всё ещё нужен, придётся объявить его явно. Это же условие важно и для рефлексии: `Class.getDeclaredConstructor().newInstance()` (современная замена устаревшего `Class.newInstance()`) требует именно публичного конструктора без аргументов, а `new` — прямая инструкция байткода (`invokespecial <init>`), которая резолвится и проверяется ещё на этапе компиляции и не накладывает такого ограничения.
    
2. **Делегирование (`this`):** Вызов `this(...)` позволяет переиспользовать логику одного конструктора в другом, чтобы не дублировать инициализацию.
    
    - _Ограничение:_ Вызов должен быть строго первой строкой — по той же причине, что и `super()`: JVM должна гарантированно выполнить ровно один «базовый» вызов (либо делегирование другому конструктору этого же класса, либо вызов конструктора родителя) до того, как начнут выполняться остальные инструкции, иначе поля рискуют быть проинициализированы дважды или в непредсказуемом порядке. Поэтому `this(...)` и `super()` взаимоисключающие: если конструктор вызывает `this(...)`, ответственность за вызов `super()` перекладывается на тот конструктор, которому делегировали — рано или поздно `super()` всё равно будет вызван (неявно или явно), просто не в этом теле.
    - _Циклическая делегация:_ Если конструкторы делегируют друг другу по кругу (`A() { this(1); }` вызывает `A(int x) { this(); }`), компилятор (`javac`) обнаруживает это на этапе сборки и падает с ошибкой "recursive constructor invocation" — до рантайма дело не доходит.
    
3. **Blank Final:** Поля, помеченные `final`, но не инициализированные при объявлении. Компилятор гарантирует, что такое поле будет проинициализировано в **каждом** конструкторе. Если хотя бы в одной ветке кода поле "забыли" — проект не соберется.

## Блоки инициализации: Скрытая логика

### Instance Initializer Block

Выглядит как обычный блок `{...}` внутри класса.

> **Senior Note:** Мало кто помнит, что на уровне байткода компилятор просто копирует содержимое этого блока в начало каждого конструктора сразу после вызова `super()` (подробный байт-код пример с несколькими конструкторами — в [[Инициализация объектов с учётом наследования]]).

Это полезно, когда нужно выполнить общую логику для всех конструкторов (например, инициализировать `final` поля сложным вычислением), не дублируя код.

### Static Initializer Block

Выполняется **один раз**, когда ClassLoader загружает класс в JVM. Идеально для настройки тяжелых статических ресурсов или драйверов. Механически это полный аналог instance-блока, но на уровне класса: все статические инициализаторы полей и static-блоки компилятор собирает по порядку объявления в один неявный метод `<clinit>` (аналог `<init>` для конструктора), который выполняется один-единственный раз. JVM дополнительно гарантирует, что `<clinit>` конкретного класса выполняется только одним потоком одновременно — если несколько потоков одновременно триггерят загрузку класса, остальные блокируются и ждут, пока инициализация не завершится. Это даёт потокобезопасность «бесплатно», без явной синхронизации — именно на этом основана идиома Enum Singleton.

## Ключевое слово `this`

`this` — это неявный параметр каждого нестатического метода, ссылка на текущий экземпляр объекта. На уровне байткода он физически передаётся как первый аргумент метода (слот локальных переменных 0) и читается инструкцией `aload_0` — именно поэтому `this` недоступен в статических методах: у них просто нет этого нулевого слота.

- **Устранение неоднозначности:** `this.name = name`.

- **Fluent API:** `return this` позволяет выстраивать цепочки вызовов (Method Chaining), что критично для паттерна Builder (см. [[Вложенные и внутренние классы, builder паттерн для инициализации объектов]]).

## Под капотом: Битва за память (Bytecode)

Когда вы пишете `Person p = new Person("Alice", 25)`, JVM выполняет сложный танец. Посмотрим на байткод:

Фрагмент кода

```
new Person          // 1. Выделение памяти под объект, заполнение полей дефолтами
dup                 // 2. Дублирование ссылки на стеке
ldc "Alice"         // 3. Подготовка аргументов
bipush 25
invokespecial <init> // 4. Вызов конструктора (инициализация)
astore_1            // 5. Сохранение ссылки в переменную p
```

**Ключевой момент:** Оператор `new` только выделяет память. Реальная работа по заполнению данными происходит в методе `<init>` (конструкторе).

## Подводные камни

1. **Порядок инициализации:** 
	1. Статические блоки (при загрузке).
    
    2. Поля экземпляра и блоки инициализации (в порядке объявления в коде).
    
    3. Тело конструктора.

3. **Рефлексия против Final:** Помните, что через `setAccessible(true)` можно изменить даже `final` поля. Это "черный ход", который стоит использовать только в тестах или глубоко в недрах фреймворков (типа Hibernate).

4. **Утечки в конструкторе:** Никогда не передавайте `this` в другие методы или потоки внутри конструктора (так называемый _this escape_). Объект еще не "достроен", и другие части системы могут увидеть его в несогласованном состоянии.
